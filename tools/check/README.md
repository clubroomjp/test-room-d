# 検査役（部屋に置くもの）

このディレクトリには、部屋のリポジトリで提出を検査するためのファイルが入っています。
ホストは、ここにあるファイルを書き換えないでください。直すときは、本体（jamroom）の
`packages/check` を直し、組み立て直してから写してください。

## 何が入っているか

| ファイル | 役割 |
|---|---|
| `check.mjs` | イシューの題名と本文を読み、形と実行を検査し、結果を書く |
| `child.mjs` | 訪問者のコードを動かす子プロセスの入口。見張り役を持つ |
| `worker.mjs` | QuickJS を載せ、ゲストのコードを動かすワーカー |
| `quickjs.wasm` | QuickJS の WASM。依存のものをそのまま置いている |
| `emit.mjs` | 結果から、ジョブの出力（`code`、`name`、`sha256`）を作る |
| `report.mjs` | 結果を、イシューのラベルとコメントに書く |
| `LICENSES.txt` | 同梱するソフトウェアの許諾の文 |
| `README.md` | このファイル |

実行に `node_modules` も、Bun も、レジストリへの接続も要りません。Node 24 だけで動きます。

## 仕組み

`.github/workflows/check-contribution.yml` が、イシューが立ったときと、本文が書き換わったときに動きます。

1. `check` のジョブは、権限も秘密も持ちません。`check.mjs` が題名と本文を読み、形を調べ、
   候補と依存先を `child.mjs` の中の QuickJS で動かします。
2. `report` のジョブだけが `Issues: write` を持ちます。訪問者のコードには触れず、
   受け取った符号から決まった文面を作って、ラベルとコメントを更新します。

外へ出すのは、符号、形を確かめた名前、提出のハッシュ値だけです。題名、本文、コード、
例外の文面は、標準出力にも、標準エラーにも、結果のファイルにも出しません。

## 守りの限界

訪問者のコードの壁は、次の 2 つです。

1. **QuickJS（WASM）の中から、ホスト側へ届かないこと。** ホストの関数は 1 つも渡していません。
   メモリの上限は WASM の 64MB で、部屋の設定では緩められません。時間は、QuickJS の割り込み、
   子の見張り役（期限＋0.5 秒）、親（期限＋2 秒）の三重で止めます。
2. **検査のジョブが、権限も秘密も持たず、使い捨ての機械で動くこと。** ここが破られても、
   ほかのイシューを書き換えたり、秘密を読んだりはできません。

子プロセスは `node --permission --allow-fs-read=<tools/check> --allow-worker` で起動し、
環境変数を渡しません。ただし、**この権限モデルは補助であって、壁ではありません。**
`--allow-worker` があるため、QuickJS の外へ抜け出した者は、`execArgv: []` を指定した
ワーカーを作れてしまい、その中では読み取り、書き込み、子プロセスの起動が止まりません。
（実験記録 `docs/experiments/2026-11-24-check-bundle.md`）

そのため、QuickJS の外側のコード（`child.mjs`、`worker.mjs`）を乗っ取られないことが前提です。
乗っ取られた場合に備えて、`check` のジョブには権限も秘密も与えず、結果を書くジョブを分けています。
